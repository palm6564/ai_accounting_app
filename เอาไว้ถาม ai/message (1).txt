1. พฤติกรรมและ Pain Points ของผู้ใช้ (Target Insights)
ไม่ชอบความซับซ้อน: พ่อค้าแม่ค้าและเจ้าของ SME ส่วนใหญ่ไม่ได้จบการบัญชี หน้าต่างใช้งาน (UI) ต้องหลีกเลี่ยงคำศัพท์บัญชีชั้นสูง เช่น "เดบิต/เครดิต" แต่ให้ใช้คำที่เข้าใจง่าย เช่น "รายรับ / รายจ่าย / กำไรสุทธิ / เงินสดคงเหลือ"

เน้นความรวดเร็วบนมือถือ (Mobile-First): การบันทึกธุรกรรมต้องทำได้จบใน 3–5 วินาที เช่น สแกนสลิปโอนเงินแล้วลงบัญชีให้อัตโนมัติ

พฤติกรรมใช้เงินปะปน: เจ้าของร้านมักใช้บัญชีธนาคารส่วนตัวร่วมกับบัญชีร้าน ระบบจึงต้องมีฟีเจอร์แยกรายการ "ส่วนตัว" ออกจาก "กระแสเงินสดของร้าน" ได้ง่าย

2. ฟีเจอร์หลักที่ต้องมี (Core Feature Set)
ระบบสแกนสลิปและใบเสร็จ (Slip & Receipt OCR): ดึงข้อมูล วันที่, เวลา, จำนวนเงิน, และเลขที่บัญชีจากสลิปธนาคารอัตโนมัติ

ระบบจัดการรายรับ-รายจ่าย (Income & Expense Tracking): จัดหมวดหมู่ค่าใช้จ่ายชัดเจน (เช่น ต้นทุนวัตถุดิบ, ค่าเช่า, ค่าแอด, ค่าแรง) เพื่อใช้วัด ROI

ระบบออกเอกสาร (Invoicing & Quotations): สร้าง ใบเสนอราคา, ใบแจ้งหนี้, และใบเสร็จรับเงิน เป็น PDF ส่งผ่าน LINE หรือ Email ได้ทันที

ระบบสต็อกสินค้าอย่างง่าย (Basic Inventory): ตัดสต็อกอัตโนมัติเมื่อมีการเปิดใบเสร็จขาย และแจ้งเตือนเมื่อสินค้าใกล้หมด

รายงานทางการเงินแบบ Real-time:

งบกำไรขาดทุนเบื้องต้น (P&L Statement)

รายงานกระแสเงินสด (Cash Flow)

สรุปสินค้าขายดีและช่องทางที่ทำกำไรได้ดีที่สุด

3. กฎหมาย บัญชี และภาษีในประเทศไทย (Tax & Compliance)
รูปแบบภาษีตามประเภทธุรกิจ:

บุคคลธรรมดา: ต้องรองรับการคำนวณภาษีเงินได้บุคคลธรรมดา (ภ.ง.ด. 90, 91, 94) และการหักค่าใช้จ่ายตามเหมา (60%) หรือตามจริง

นิติบุคคล: ระบบหลังบ้าน (Backend) ต้องลงบัญชีแบบคู่ (Double-Entry Bookkeeping) เพื่อให้ส่งต่อข้อมูลให้สำนักงานบัญชีได้

ภาษีมูลค่าเพิ่ม (VAT 7%):

เมื่อธุรกิจมีรายได้เกิน 1,800,000 บาท/ปี ต้องจด VAT ระบบต้องสามารถแยก Vat In (ภาษีซื้อ) และ Vat Out (ภาษีขาย) พร้อมออกรายงาน ภ.พ. 30 ได้

ภาษีหัก ณ ที่จ่าย (Withholding Tax): รองรับการหักภาษี ณ ที่จ่ายตามประเภทบริการ (เช่น ค่าเช่า 5%, ค่าบริการ 3%, ค่าโฆษณา 2%) และออกใบ 50 ทวิได้

ระบบ e-Tax Invoice / e-Receipt & e-Withholding Tax: ต้องศึกษา API ของกรมสรรพากรเพื่อรองรับการส่งข้อมูลภาษีอิเล็กทรอนิกส์ในอนาคต

พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA): ต้องมีระบบเข้ารหัสข้อมูลลูกค้า สลิป และยอดขาย เพื่อป้องกันการรั่วไหลของข้อมูลทางการเงิน

4. สถาปัตยกรรมเทคนิคและการเชื่อมต่อ (Tech Architecture & Integrations)
Bank API & Open Banking: การเชื่อมต่อ API ตรวจสอบสลิปโอนเงิน (Slip Verification API เช่น SlipOK, EasySlip)

LINE Official Account (LOA) Integration: ให้ผู้ใช้บันทึกรายรับ-รายจ่าย หรือรับการแจ้งเตือนยอดขายผ่าน LINE Chatbot ได้โดยไม่ต้องเปิดแอป

Data Security & Cloud Backup: การจัดการระบบฐานข้อมูลที่มีความปลอดภัยสูง (Encryption at rest and in transit) และรองรับการทำ Offline Mode เบื้องต้นหากไม่มีอินเทอร์เน็ต

Data Export: ต้องรองรับการส่งออกไฟล์ CSV, Excel หรือไฟล์ฟอร์แมตที่โปรแกรมบัญชีมาตรฐาน (เช่น Peak, FlowAccount, Express) สามารถนำไปใช้งานต่อได้
